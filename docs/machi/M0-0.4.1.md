# M0 Kernel — 0.4.1 Store

**Primary:** `0.4.1` Store  
**Port:** `machi.kernel.store.Store`  
**Adapter:** `machi.adapters.persistence.file_store.FileStore`  
**Proof contract:** `StoreProof` (`kernel.store.proof@1`) — test data, not RegistrySeed  
**CLI:** `machi kernel store-put|store-get --store-dir DIR --key KEY`  
**Layout:** `<injected root>/<kind>/<key>.json`

This is not a substitute for [ARCHITECTURE.md](ARCHITECTURE.md).
It records what 0.4.1 reused from Kultrun and what it refused.

## Why now

M0 deferred entity persistence because `kernel.alive` only needed an
append journal. `1.3.2 RegistrySeed` needs addressable entity records.
The journal cannot replace that. Ownership of the port stays Kernel.

## REUSED CONCEPTS

- Port in Kernel, adapter in `adapters/persistence`.
- Caller-owned logical key, refused rather than sanitized.
- One JSON file per record; kind namespaces the directory.
- Self-describing document (`kind`, `schema_version`, `record_key`).
- Temp file + fsync before publication.
- Temporaries are never treated as records.

## SELECTIVELY REUSED CODE

Key-validation idea from `kultrun.kernel.persistence.validate_record_key`.
Layout `<kind>/<key>.json` from `kultrun.adapters.persistence.file_store`.
Not copied as a module. Kultrun `put` overwrite, `get`→None, `delete`,
`keys`, `records`, and `reconcile` were not ported.

## REJECTED LEGACY PATTERNS

- Using FileStore as the event log.
- Silent overwrite via `os.replace`.
- Missing records as `None` (Machi uses typed `NotFoundError`).
- `delete` / listing / reconcile / query.
- Kernel choosing `/var/lib/...`.
- Event-sourcing entities from EventRecord.
- A `StoreId` that replaces domain IDs.

## ENHANCEMENTS MADE

- Exclusive create (`os.link`); identical re-entry returns the stored
  record; conflicting content fails closed.
- Malformed existing records fail closed and are not overwritten.
- Corruption of entity B does not prevent reading A or C.
- Store does not import Journal, Install, or environment configuration.
- Proof telemetry `kernel.store.proved` is optional, `restricted`, and
  omits path and entity body.
