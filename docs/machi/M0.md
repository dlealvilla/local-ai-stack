# M0 Kernel — implementation notes

**Primary:** `0.3.1` EventRecord  
**Additional:** `0.1.1`, `0.1.2`, `0.2.1`, `0.3.2`, `0.5.1`  
**Artifact:** `machi` 0.1.0 via `python tools/build_machi.py`  
**First event:** `kernel.alive` (`public_ops`)

This is not a substitute for [ARCHITECTURE.md](ARCHITECTURE.md).
It records what the first code increment reused from Kultrun and what
it refused.

## REUSED CONCEPTS

- Unresolved has no truth value; unknown is not zero and not a pass.
- Contracts are frozen dataclasses tagged with `kind` + integer
  `schema_version`; persist the document form, not pickle.
- Minted IDs are prefixed and typed; names are a separate type.
- Build identity is shipped inside the wheel (`BUILD.json`); a
  checkout must say it is a checkout.
- Journal defects are facts; prior valid records remain readable.
- UTC-only timestamps; naive datetimes are refused.
- Composition root is the only module that names adapters.

The JSONL journal and `EventRecord` envelope are new. They are not a
port of `OperationalFact` or `vendor.TelemetryRecord`.

## REJECTED LEGACY PATTERNS

- Three overlapping telemetry records (`kernel.Event`,
  `OperationalFact`, `vendor.TelemetryRecord`).
- Entity `FileStore` as the M0 event log.
- Kernel choosing `/var/lib/...` or an install state root.
- Stage numbers, `.kultrun-owner.json`, DeploymentRun `drun_`.
- Event-sourcing operational state.
- Fabricating DeploymentWitness in M0.
- Shipping Machi inside the Kultrun wheel.

## ENHANCEMENTS MADE

- One envelope (`event_record` v1) with explicit privacy, Block and
  Component IDs, and a nested versioned payload.
- `install_*` / `host_id` exist on the envelope before Install exists,
  as Unresolved, so M1 does not redesign the document.
- Journal readback ignores additive unknown fields; the API still
  forbids them. Malformed lines become `journal_defect` facts.
- Separate `pyproject.machi.toml` so the artifact cannot bundle
  Kultrun.
