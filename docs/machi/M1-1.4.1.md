# M1 Install — 1.4.1 InstallRunStore

**Primary:** `1.4.1` InstallRunStore  
**Consumes:** `InstallRecord` (1.1.1), Kernel `Store` (0.4.1),
`BuildIdentity`, Clock / typed IDs  
**Not in this increment:** Discover, Steward, HostId, run history,
upgrades, uninstall  
**Event:** `install.bound` (`restricted`; resolved `install_id` and
`install_run_id`; `host_id` unresolved)  
**CLI:** `machi install establish-run --store-dir DIR [--state-root PATH] [--journal-dir DIR]`  
**Record:** `InstallRunRecord` (`install_run@1`)  
**Store key:** `InstallId.value` (`inst_…`)

This is not a substitute for [ARCHITECTURE.md](ARCHITECTURE.md).
It records what 1.4.1 reused from Kultrun and what it refused.

## What 1.4.1 proves

This installation has one durable installation-journey identity
(`INSTALL_RUN_PRESENT` / `InstallRunId`) correlated to its
`InstallRecord`.

## What 1.4.1 does not prove

The current process. The current CLI invocation. The current host.
Run completion. Dual ownership. Cleanup rights. That a copied tree is
the same installation.

**HostId created here: NO.**  
**Destructive authorization produced: NO.**  
**Run history implemented: NO.**

## Store arrangement

Composition injects one control-plane Store. 1.3.2, 1.1.1, and 1.4.1
use different contract kinds under the same root. Domain code does not
choose the path. Local proofs keep that Store outside the claimed
state root.

## REUSED CONCEPTS

- Journey identity is reused across CLI processes, not minted per command.
- First creation is a normal case; re-entry returns the same id.
- Fail closed on malformed JSON; corruption is not absence.
- Typed prefixed `irun_` identifier (Kultrun `DeploymentRunId` lesson,
  Machi prefix already existed in Kernel).
- Create-once persistence via injected Store exclusive create.

## SELECTIVELY REUSED CODE

None copied. Kultrun `DeploymentRunStore` was read as evidence only.

## REJECTED LEGACY PATTERNS

- Singleton Store key `"current"` (cannot host two installations).
- Coupling the run to `HostId`.
- `IN_PROGRESS` / `COMPLETED` / `FAILED` lifecycle and `put` overwrite.
- Process-local `_loaded` cache as the source of truth.
- `store.get` returning `None`; minting over unreadable state.
- `install.started` as a second 1.4.1 event (architecture named
  `install.bound` as the Block 1 domain event).
- Run rotation, history, retry, reset, or installer orchestrator.

## ENHANCEMENTS MADE

- Distinct `InstallRunRecord` keyed by existing `InstallId`.
- Consumes `InstallRecord` only; does not re-bind, re-mark, or re-seed.
- Concurrent first-create: Store conflict re-reads the persisted winner.
- Build fields are creation provenance; a later BuildIdentity re-enters.
- Event `install.bound` resolves `install_id` and `install_run_id` and
  leaves `host_id` unresolved. Earlier events are not rewritten.
