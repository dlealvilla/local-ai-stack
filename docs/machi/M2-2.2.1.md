# M2 Discover — 2.2.1 Memory observer

**Primary:** `2.2.1` Memory observer  
**Consumes:** 2.1.1 OS family; Kernel Clock / Unresolved / EventRecord;
optional M1 InstallId and InstallRunId from composition  
**Not in this increment:** available memory, swap, cgroup/execution
limit, Windows native reader, HostId, HostProfile, NVIDIA, mounts,
capacity  
**Event:** `discover.memory.observed` (`public_ops`; `host_id`
unresolved; Install correlation only when composition supplies it)  
**CLI:** `machi discover memory [--state-root PATH] [--store-dir DIR] [--journal-dir DIR]`  
**Record:** `MemoryObservation` (`memory_observation@1`)  
**Persistence:** event only; no Store entity

This is not a substitute for [ARCHITECTURE.md](ARCHITECTURE.md).
It records what 2.2.1 reused from Kultrun and what it refused.

## What 2.2.1 proves

This environment reports a physical/system memory total in integer
bytes, observed through a replaceable adapter, with compact raw
evidence retained.

## What 2.2.1 does not prove

That Machi may safely consume that many bytes. That swap or cgroup
limits exist. That a unique HostId exists. That Discover is complete.

**HostId created here: NO.**  
**HostProfile created here: NO.**  
**Safe allocatable memory calculated here: NO.**

## Core vs adapter

`MemoryObservation` and the observer port live in `machi.discover`.
`NativeMemoryObserver` selects a platform provider.
`LinuxProcMemoryProvider` owns `/proc/meminfo` parsing.
`MacOSSysconfMemoryProvider` owns `os.sysconf`. Composition selects
the native observer, not a vendor class. OS family comes from 2.1.1.

## REUSED CONCEPTS

- Adapters observe; core owns normalized meaning.
- Bytes are canonical; KiB converts as `n * 1024`.
- Unknown is not zero.
- Observation is not mutation and not admission.
- Kultrun `MemTotal` as physical total; `MemAvailable` and cgroup
  `memory.max` exist in Kultrun but are deferred here.

## SELECTIVELY REUSED CODE

None copied. Kultrun `NativeLinuxProvider._read_meminfo` was read as
evidence only.

## REJECTED LEGACY PATTERNS

- `MemoryFacts` mega-contract with unified-accelerator and limit fields
  in this increment.
- Treating `MemTotal` as SAFE / allocatable memory.
- psutil.
- Subprocess `sysctl` / `vm_stat` in production.
- Active buffer-allocation probing.
- HostId from RAM size.
- Collapsing physical RAM and cgroup limit into one number.

## ENHANCEMENTS MADE

- Field name `physical_total_bytes` so it cannot be read as capacity.
- Explicit `MemorySource` (`linux_proc` / `sysconf` / `unobserved` /
  `unsupported`).
- Windows is `unsupported` + Unresolved, never `0`.
- Event privacy `public_ops` consistent with OS/arch machine facts.
