# M9 — Serve (native vLLM, local)

**Primary:** `9` Serve  
**Does not:** discover hardware, derive Capacity, provision Foundation,
acquire a model, compose a plan, or admit a reservation

Serve starts the runtime a current plan already reserved. The start
requires `execution_authorized` from Admit. A bare plan does not launch.

The generic `ServingInstance` is one logical deployment. It records the
plan, reservation, foundation generation, artifact, provider, executor,
endpoint identity, lifecycle, health, and a provider-evidence id. It
does not require a pid, an argv, or a port. Those live on
`serve.native_process`.

This increment's provider is native vLLM. The command is built in the
adapter from the planned settings and the verified interpreter and
artifact. The warehouse path is the load path. The OpenAI model name
is the artifact id, so the inference request does not send a filesystem
path. Remote code is not enabled. The bind scope is loopback.
Readiness is the runtime health check, not process existence.

Stop confirms the process is dead before the instance is `stopped`.
`release_after_stop` calls Admit's release only then. While the process
is alive the reservation stays held. Serve does not implement a second
reservation ledger.

A live ready instance is returned again instead of spawning another
process. A second stop converges. A recreated service will not adopt a
pid whose start stamp does not match. There is no automatic restart.

`DeploymentWitness` is still a Kernel projection and is not implemented
here (`M-9-01`). Policy version is `m9.serve.1`.
