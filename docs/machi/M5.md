# M5 — Foundation (Tier 2)

**Primary:** `5` Foundation  
**Does not:** choose a model, download weights, admit a workload,
select serving settings, or start a server

Foundation answers whether this host can hold a Machi-managed native
vLLM environment. The family is `direct`, the engine is `vllm`, and
the executor is `native_process`. NVIDIA CUDA and AMD ROCm are the
concrete providers. They share one resolver, one generation layout,
and one verification contract.

The managed interpreter is Python 3.12, created under
`foundation/generations/<id>/venv`. CUDA installs `vllm==0.18.0` from
PyPI with the torch backend left to the installer. ROCm installs
`vllm==0.18.0+rocm700` from the public ROCm wheel index. A verified
generation is reused. A failed verification is not treated as healthy.
A different pin is a new generation. Historical generations are not
deleted.

The AMD artifact is the `rocm700` recipe: vLLM `0.18.0`, Python
`3.12`, ROCm line `7.0` (not a minimum), glibc `>= 2.35`, and the
sonames `libamdhip64.so`, `librocblas.so`, and `libmpi_cxx.so.40`.
ROCm `6.1` is rejected before install. A missing soname is
`prerequisite_blocked` and does not install the wheel.

Inspection is the default and does not install. Provision is explicit
and requires a verified Machi-owned state root. The package cache stays
under that root. System Python is not the runtime. Drivers are not
modified. Prerequisite readiness is consumed when the caller supplies
it; Foundation does not remediate vendor CLIs.

Capacity is consumed and not overruled. The conservative requirement
is 12 GiB persistent, 8 GiB transient, and 8 GiB of safe memory. If
those SAFE values are missing or smaller, the result is
`insufficient_capacity`.

`READY` requires a managed interpreter, a vLLM import, a version that
matches the pin, a backend coherent with the selected provider, and a
discoverable API entrypoint module. Serving remains unsupported.
Streaming is declared by the installed entrypoint and is not verified.
Structured output, LoRA, and metrics stay unresolved.

If native vLLM is unsupported, the result is a typed refusal. No other
runtime is substituted.

`MEANINGFUL_SETTINGS_REMAIN_TYPED_AND_INSPECTABLE=YES`.

Tier-3 executors, engines, upgrades, and cleanup are `M-5-01`.
