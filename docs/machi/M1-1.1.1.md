# M1 Install — 1.1.1 InstallRecord

**Primary:** `1.1.1` InstallRecord  
**Consumes:** `BuildIdentity` (Kernel), `StateRootBinding` (1.2.1),
`LocalOwnershipEstablishment` (1.3.1), `LocalOwnershipRegistryEstablishment`
(1.3.2), Kernel `Store` (0.4.1)  
**Not in this increment:** `1.4.1`, Discover, Steward, upgrades, uninstall  
**Event:** `install.record.established` (`restricted`; resolved `install_id`)  
**CLI:** `machi install establish-record --store-dir DIR [--state-root PATH] [--journal-dir DIR]`  
**Record:** `InstallRecord` (`install_record@1`)  
**Store key:** local `marker_id` (`lown_…`)

This is not a substitute for [ARCHITECTURE.md](ARCHITECTURE.md).
It records what 1.1.1 reused from Kultrun and what it refused.

## What 1.1.1 proves

This coherent Machi-owned state has a stable installation identity
(`INSTALL_RECORD_PRESENT` / `InstallId`).

## What 1.1.1 does not prove

The current software version. The current host. The current run.
Dual ownership. Cleanup rights. That a copied tree is the same
installation.

**InstallRunId created here: NO.**  
**HostId created here: NO.**  
**Destructive authorization produced: NO.**

## Store arrangement

Composition injects one control-plane Store. 1.3.2 and 1.1.1 use
different contract kinds under the same root. Domain code does not
choose the path. Local proofs keep that Store outside the claimed
state root.

## REUSED CONCEPTS

- Installation identity is never regenerated over unreadable state.
- First creation is a normal case.
- Identity belongs to installation evidence, not to a disposable host.
- Typed prefixed `inst_` identifier (Kultrun `InstallationId` prefix).
- Create-once persistence via injected Store.
- Fail closed on malformed JSON; corruption is not absence.

## SELECTIVELY REUSED CODE

None copied. Kultrun `PlatformStateStore`, `DeploymentRunStore`, and
`PlatformState` were read as evidence only.

## REJECTED LEGACY PATTERNS

- Singleton Store key `"current"` (cannot host two installations).
- `platform_version` as current software on the identity record.
- `store.get` returning `None`; `put` overwrite.
- Embedding administrator/subject records in the installation document.
- `DeploymentRun` / `InstallRun` minted at identity creation.
- HostId on the identity record.
- Absolute paths.
- Artifact SHA invented from filenames or source trees.

## ENHANCEMENTS MADE

- Distinct `InstallRecord` keyed by existing `marker_id`.
- Build fields are creation provenance; a later BuildIdentity re-enters.
- Coherence of binding fingerprint, marker, and registry required
  before minting.
- Event `install.record.established` resolves `install_id` and leaves
  `install_run_id` / `host_id` unresolved. Earlier events are not rewritten.
- No artifact SHA field: `BuildIdentity` does not carry a wheel hash.
