# M1 Install — 1.3.2 RegistrySeed

**Primary:** `1.3.2` RegistrySeed  
**Consumes:** `StateRootBinding` (1.2.1), `LocalOwnershipEstablishment` (1.3.1), Kernel `Store` (0.4.1)  
**Not in this increment:** `1.1.1`, `1.4.1`, Steward, cleanup  
**Event:** `install.ownership.registry_seeded` (`restricted`)  
**CLI:** `machi install seed-registry --registry-store-dir DIR [--state-root PATH] [--journal-dir DIR]`  
**Record:** `LocalOwnershipRegistryRecord` (`local_ownership_registry_record@1`)  
**Store key:** local `marker_id` (`lown_…`)

This is not a substitute for [ARCHITECTURE.md](ARCHITECTURE.md).
It records what 1.3.2 reused from Kultrun and what it refused.

## Registry authority

**Location:** the customer's local Machi control plane.  
**Vendor / cloud / website / OpenAI dependency:** no.  
**Offline capable:** yes.

## What 1.3.2 proves

The local Machi control plane has a durable registry row citing this
local marker identity and root fingerprint (`REGISTRY_SEED_PRESENT`).

## What 1.3.2 does not prove

Dual ownership. Cleanup rights. Install identity. That the claimed
tree may be deleted. A copied filesystem tree.

**Destructive authorization produced by 1.3.2: NO.**

## REUSED CONCEPTS

- Dual ownership as two authorities (local marker + registry). Path
  heuristics never delete.
- Registry keyed by the same stable identity as the local marker.
- Fail closed on identity / fingerprint mismatch.
- Re-entry must not mint a second identity or rewrite `created_at`.
- Store is injected; domain logic does not choose a host path.
- Malformed JSON is not absence.

## SELECTIVELY REUSED CODE

None copied. Kultrun `OwnershipService`, `assert_owned`, `classify`,
`reconcile`, `cleanup_disposable`, `forget`, `delete_owned_root`, and
`OwnershipRecord` (which stored absolute `managed_root` and was both
marker and registry document) were read as evidence only.

## REJECTED LEGACY PATTERNS

- Same `OwnershipRecord` written as both marker file and registry row.
- Storing absolute `managed_root` on the registry document.
- `store.put` overwrite of an existing row.
- `get` → `None`; malformed JSON treated as absence.
- `rglob` sibling discovery and `reconcile` reconstructing registry
  from markers.
- `classify` / cleanup / `shutil.rmtree`.
- Minting `HostId` or a second `OwnershipId` merely to have a Store key.
- Calling the result `OwnershipRecord` or `ownership.verified`.

## ENHANCEMENTS MADE

- Distinct contract `LocalOwnershipRegistryRecord`; Steward keeps
  `OwnershipRecord` for later dual-proof evaluation.
- Registry Store location is injected and, in tests, a separate tree
  from the claimed state root.
- Consume `StateRootBinding` + `LocalOwnershipEstablishment`; do not
  rediscover `.machi-owner.json` or read `MACHI_STATE_ROOT`.
- Exclusive Store create; get-first re-entry so timestamps stay
  immutable even though a newly minted contract would not equal the
  stored one.
- Event privacy `restricted`; payload has marker id and fingerprint,
  never the absolute root or Store path.
- `dual_ownership` and `destructive_authorization` remain false.
