# M8 — Admit (Tier 2, local)

**Primary:** `8` Admit  
**Does not:** start a process, load a model, provision Foundation,
or enforce the hold with cgroups or a container

Admit answers whether the exact resources in one current plan can be
reserved on this host without exceeding SAFE capacity. The answer is
one `ResourceReservation` or a typed refusal. A refusal consumes
nothing.

Repository components stay `8.1` Snapshot, `8.2` ResourceManager, and
`8.3` Reservation states. The snapshot is the current
`CapacityEnvelope`. There is no second capacity type. The file-store
log and the POSIX lock are adapters. No vendor allocator is selected.

A hold requires a successful plan, a matching configuration and
request, plan currency `none` from the caller, and the same capacity
evidence id the plan cited. Admit does not recompute the plan. A
stale plan returns `stale_plan` and the underlying plan code. A
different evidence id returns `stale_capacity_input`.

Accounting uses SAFE bytes only. Host memory is one pool. Accelerator
memory is per exact device identity. Storage uses the largest single
usable domain and does not add domains together. Persistent overflow
is reported before transient overflow. Unresolved SAFE memory or
storage is `capacity_unresolved`, not zero. Two plans that each
request the whole SAFE host or accelerator budget cannot both be
admitted. Admit does not shrink the request or choose another device.

`cpu_count` is stored and is not subtracted from a pool. Capacity
does not publish SAFE CPU bytes. That gap is `M-8-02`.

Policy version is `m8.admit.1`. The reservation id is a hash of that
policy, the plan id, the fingerprint, the request id, the capacity
evidence id, and a sequence. The sequence stays 0 while the hold is
active, so a repeat returns the same id. After release, the sequence
increases and a later hold is a new id. Release writes a
`ReservationRelease` and leaves the reservation record in place.

States in this increment are `reserved` and `released`. `active` is
omitted until Serve has a process to report. `execution_authorized`
is true only for a `reserved` hold whose plan id, fingerprint, and
accelerator identity match the configuration. A bare plan is not
authorization.

The file lock covers the read, the fit check, and the exclusive
create. Recreating the manager from the store keeps unreleased holds
in the accounting. Reconciliation reports a missing accelerator, a
SAFE envelope that shrank below the reserved aggregate, or a
malformed record. It does not rewrite holds.

`MEANINGFUL_SETTINGS_REMAIN_TYPED_AND_INSPECTABLE=YES`.

This document records the local candidate. It is not a physical
admission proof. AMD foundation qualification remains `M-5-AMD-01`.
OS enforcement and the rest of the later depth are `M-8-01`.
