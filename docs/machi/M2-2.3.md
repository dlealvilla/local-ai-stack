## What 2.3 proves locally

Accelerator hardware can be observed through a vendor-neutral
capability. NVIDIA, AMD, Intel, and Apple translate into the same
`AcceleratorObservation`. Missing vendor tooling is unavailable, not a
measured zero-GPU rack. Unified topology does not invent dedicated
VRAM. One provider exception cannot erase another provider's devices.

Four-provider local acceptance of the new combined wheel is recorded
in [M2-2.3-FOUR-PROVIDER-LOCAL.md](M2-2.3-FOUR-PROVIDER-LOCAL.md).
Fresh NVIDIA, AMD, and Intel physical proof of that exact SHA remains.
Apple physical remains deferred.

## Core vs adapter

`AcceleratorObservation`, `AcceleratorDevice`,
`AcceleratorProviderReport`, and `AcceleratorObserver` live in
`machi.discover`. `NativeAcceleratorObserver` selects applicable
providers in order NVIDIA, AMD, Intel, Apple and concatenates generic
devices. `NvidiaAcceleratorProvider` owns `nvidia-smi` CSV parsing.
`AmdAcceleratorProvider` owns `amd-smi` JSON parsing.
`IntelAcceleratorProvider` owns Intel SMI discovery JSON parsing.
`AppleAcceleratorProvider` owns `system_profiler` JSON parsing.
Composition wires only the native observer.

## Memory topology

Generic fact, not a VRAM synonym:

- `discrete` — dedicated accelerator memory may be reported in bytes
- `unified` — shared with system memory; dedicated total stays Unresolved
- unknown stays Unresolved, never `0`

## Provider inspection status

Separate from `ObservationStatus` (shared with OS/arch and memory):

- `observed` — inspection succeeded, `0..N` devices (empty success is allowed)
- `not_applicable` — host facts make this provider meaningless
- `unavailable` — tool/API missing
- `unsupported` — reserved
- `failed` — non-zero exit, timeout, malformed output, or isolated inspect exception

Overall observation status is `normalized` when at least one provider
observed, else `unobserved`.

## REUSED CONCEPTS

- Adapters observe; core owns normalized meaning.
- Unknown is not zero.
- Observation is not mutation and not admission.
- Kultrun: missing `nvidia-smi` is unavailable, not zero GPUs.
- Kultrun: `memory.total` MiB converts as `n * 1024 * 1024`.
- Kultrun: injected CSV replay for deterministic tests.
- Kultrun: machine-readable `--query-gpu` / `--format=csv,noheader,nounits`.

## SELECTIVELY REUSED CODE

None copied. Kultrun `NvidiaProvider` was read as evidence only.

## REJECTED LEGACY PATTERNS

- PCI bus as required generic identity.
- Silently skipping malformed `nvidia-smi` rows.
- Naive `str.split(",")` (breaks quoted model names).
- hwloc vs NVIDIA assignment authority / `reports_accelerator_assignment`.
- Driver version as a generic Discover field.
- Treating NVIDIA as the Accelerator Discovery model.
- Copying `hw.memsize` / `physical_memory` into Apple GPU memory.
- Copying MI300A HBM into dedicated VRAM.
- Using Intel Max Mem Alloc Size as total accelerator memory.
- Treating Intel tiles as top-level generic devices.
- `pynvml`, CUDA, torch, `amdsmi`, Level Zero as base-wheel dependencies.
- `rocm-smi`, sysfs, DRM, or raw PCI as independent device sources.
- Collapsing unavailable / not-applicable / failed into `0` devices.
- Reducing multi-GPU hosts to a primary GPU.
- Summing VRAM in Discover.

## ENHANCEMENTS MADE

- Vendor-neutral `AcceleratorObservation` with `0..N` devices.
- `ProviderInspectionStatus` so unavailable is not a device count.
- Unified topology forbids a normalized dedicated total.
- `csv` module parsing for NVIDIA quoting.
- Apple identity from model slug, not PCI.
- `AcceleratorSource` provenance `amd_smi` and `xpu_smi` (no schema bump).
- Isolated provider exceptions retain sibling observations.
- Architecture tests isolate domain, each vendor I/O, and composition.

## Deferred

- `VISIBLE_DEVICE_SCOPE_DEFERRED`: NVIDIA MIG, AMD CPX/XCP, SR-IOV,
  Intel VFs, tiles as independent devices, container vs physical
  inventory.
- Intel iGPU / consumer Arc coverage beyond tool-visible GPUs.
- AMD alternate sources (`rocm-smi`, sysfs, DRM).
- Apple Silicon physical proof.
- Fresh NVIDIA/AMD/Intel physical proof of the four-provider candidate.
- High device-count systems above the 64-device observation bound.
- HostProfile aggregation.
- Capacity safe/available VRAM.
- Optional NVIDIA PCI/driver provenance if a later consumer needs it.
