## What 2.5.1 proves

A selected vendor CLI can be inspected, diagnosed, planned, and — only
under an explicit remediate policy — mutated through an allowlisted
interpreter-dependency action targeting the interpreter that CLI
actually uses. Mutation is never assumed successful: the adapter
re-inspects and verifies. READY is `NO_OP`. Discover remains
read-only.

The first remediable instance is stock ROCm `amd-smi` failing with
`ModuleNotFoundError: No module named 'yaml'`. Diagnosis is the
generic missing-module class. The allowlist maps `yaml` →
`PyYAML==6.0.2`. That pin is an instance, not the architecture.

## What 2.5.1 does not prove

That GPU drivers were installed. That a package manager exists. That
PyPI will be available in air-gapped deployments. That every AMD SKU
is ready. That Discover observations changed. That ResourceManager
admitted anything. That serving configuration was chosen.

**Discover mutated here: NO.**  
**ResourceManager used here: NO.**  
**Optimizer used here: NO.**  
**PyYAML added to the Machi wheel: NO.**  
**Driver installation: NO.**

## Core vs adapter

`PrerequisiteReadiness` orchestration, contracts, policy, and events
live in `machi.prerequisites`. Host I/O lives in
`machi.adapters.prerequisites`. Composition (`machi.main`) wires
`AmdSmiPrerequisiteAdapter`. Discover must not import this package.

## Policy and configuration

| Mode | Inspect | Diagnose | Plan | Mutate |
|---|---|---|---|---|
| `observe_only` | yes | yes | no | no |
| `plan_only` (default) | yes | yes | yes | no |
| `remediate` | yes | yes | yes | allowlisted only, then verify |

Inspectable settings on every report: `policy.mode`,
`policy.dependency_source`, plus adapter settings
(`allowlist.interpreter_dependencies`, `inspect.timeout_seconds`,
`remediate.timeout_seconds`). Provenance is
`product_default` / `policy` / `administrator` / `detected_environment`.

Selected policy is desired/selected. Inspection and verification are
effective. Recommended values are the product defaults. Admitted is
not used here (no ResourceManager).

Dependency source kinds are represented now: `network`,
`local_artifact`, `managed_cache`, `unavailable`. Only `network` is
executed in the current adapter, as the bounded development proof.
Local-artifact and managed-cache plans are `BLOCKED` rather than
pretending a cache exists.

## AMD adapter

Inspection sequence:

1. Linux-only; otherwise `not_applicable`.
2. Locate `amd-smi` on `PATH`.
3. Resolve interpreter from the executable shebang (`absolute` or
   `/usr/bin/env` + `which`); fail closed if ambiguous.
4. Invoke `amd-smi list --json` with timeout.
5. Classify: ready / missing executable / timeout / permission /
   missing interpreter module / unrecognized failure.

Remediation argv is exactly:

```text
<cli-interpreter> -m pip install PyYAML==6.0.2
```

No shell. No user-supplied package name. No install into Machi's own
environment unless that environment is the CLI interpreter.

## Coverage model

Denominator is **behavior/software-environment**, not GPU market:

- READY / missing executable / missing allowlisted module /
  unrecognized / timeout / permission / not-applicable
- observe_only / plan_only / remediate
- success / failed mutation / idempotent second cycle
- interpreter identity / ambiguous interpreter / forged package
- network vs represented offline source

Physical campaign (after local freeze): one owned MI300X stock ROCm
image. Test A broken → remediated. Test B READY → `NO_OP`. Test C
policy gating is local unless physical repetition adds information.
