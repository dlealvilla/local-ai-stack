## What 2.4.1 proves

Machi can observe the filesystem/mount topology visible in its own
namespace: mount points, sources, filesystem types, normalized
options, read-only/read-write flags, reported total/free/available
bytes, backing-store identity when the platform exposes it, a bounded
storage-class, native quota *status* (not specialist limits), path
access facts, and optional tiny write-probe evidence.

Reported filesystem capacity, a successful bounded write, and SAFE
deployable capacity remain distinct. 2.4.1 never computes
`SAFE_STORAGE_BYTES`.

## What 2.4.1 does not prove

That a path has X GiB usable. That two overlay mounts share host
backing. That a quota will not fire after a few GiB. That `/models`
or `/workspace` belongs to Machi. That a network mount is fast enough.
That Capacity may admit a reservation.

**Discover mutated here:** only an optional tiny exclusive temp file
with guaranteed cleanup, and only when `--write-probe` / bounded
policy is selected. Default is off.  
**ResourceManager used here: NO.**  
**Steward ownership inferred here: NO.**  
**SAFE storage computed here: NO.**

## Core vs adapter

`MountObservation` and descriptive suitability live in
`machi.discover`. Host I/O lives in `machi.adapters.discover`.
`NativeMountObserver` selects Linux or macOS. Composition
(`machi.main`) wires the native observer, not the platform parsers.

Classification is provider-owned. Suitability is a descriptive
signal with reasons, not deployment authority.

## Reported vs proven vs SAFE

| Fact | Owner | Meaning |
|---|---|---|
| `total_bytes` / `free_bytes` / `available_bytes` | 2.4.1 | what the filesystem reported (`f_blocks` / `f_bfree` / `f_bavail` × fragment size) |
| bounded write probe | 2.4.1 optional | this path accepted this tiny payload |
| native quota status | 2.4.1 | advertised-but-unread, unsupported, or unresolved — not a specialist read |
| SAFE deployable bytes | Capacity later | may consume 2.4 facts plus Steward, reservations, and Sonar |

`free_bytes` is not Machi-usable bytes. `available_bytes` is not SAFE.
Unknown is `Unresolved`, never `0`.

## Configuration

Inspectable typed settings on every observation:

`write_probe.policy`, `write_probe.max_bytes`,
`filesystem.included_classes`, `filesystem.ignored_classes`,
`managed_root.candidates`, `network.mount_policy`,
`pseudo.mount_policy`, `read_only.handling`.

Defaults: probe disabled; payload 64 bytes (bound 1..4096); pseudo
is topology not candidacy; network mounts are observed not rejected;
Discover infers no ownership from path names.
`MEANINGFUL_SETTINGS_REMAIN_TYPED_AND_INSPECTABLE=YES`.

## Privacy

Mount points are operationally necessary on the in-process
`MountObservation` and CLI document. The journaled event carries
counts, class histogram, probe policy, and namespace — not mount
points, sources, or customer filenames.
