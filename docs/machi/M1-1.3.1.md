# M1 Install — 1.3.1 SelfOwnershipMarker

**Primary:** `1.3.1` SelfOwnershipMarker  
**Consumes:** `StateRootBinding` from `1.2.1`  
**Not in this increment:** `1.3.2`, `1.1.1`, `1.4.1`  
**Event:** `install.ownership.local_marked` (`restricted`)  
**CLI:** `machi install mark-local [--state-root PATH] [--journal-dir DIR]`  
**Marker file:** `.machi-owner.json`

This is not a substitute for [ARCHITECTURE.md](ARCHITECTURE.md).
It records what 1.3.1 reused from Kultrun and what it refused.

## What 1.3.1 proves

A valid Machi local ownership marker exists for this bound state
root (`LOCAL_MARKER_PRESENT`).

## What 1.3.1 does not prove

Dual ownership. Install identity. Cleanup rights. A copied file
from another root. A Kultrun tree. Unknown customer content.

**Destructive authorization produced by 1.3.1: NO.**

## REUSED CONCEPTS

- Dual ownership as two authorities (local marker + central registry).
  Path heuristics never delete.
- Fail closed on identity mismatch.
- `created_by` / provenance is not inferred from the path.
- Re-entry must not mint a second identity.
- Never guess ownership from directory names.

## SELECTIVELY REUSED CODE

None copied. Kultrun’s `.kultrun-owner.json` writer, `OwnershipService`,
`assert_owned`, sibling `rglob`, and `load_marker` treating malformed
JSON as absence were read as evidence only.

## REJECTED LEGACY PATTERNS

- Filename `.kultrun-owner.json`.
- Storing absolute `managed_root` on the marker.
- `write_text` overwrite of an existing marker.
- Treating malformed JSON as absence (`None`).
- Minting `HostId` / Install identity at mark time.
- `assert_owned` claiming any mkdir’d tree, including unknown files.
- Sibling discovery (`rglob` of owner files).
- Cleanup, reclaim, or `shutil.rmtree`.
- Calling the local result `OwnershipRecord` or `ownership.verified`.

## ENHANCEMENTS MADE

- Marker filename `.machi-owner.json`.
- Dedicated `LocalOwnershipId` (`lown_`), not `InstallId`.
- Root binding via the 1.2.1 SHA-256 fingerprint; a copied marker is
  invalid on another root.
- Exclusive create: temp file, fsync, `os.link` to dest (fails if dest
  exists), directory fsync, unlink temp.
- Malformed / unsupported / wrong-product markers fail closed and are
  never repaired or overwritten.
- First-claim policy: Machi-created new roots, empty existing roots, and
  known M0/1.2.1 `journal/events.jsonl` bootstrap may be marked.
  Unknown pre-existing content is refused. No adoption workflow.
- `.kultrun-owner.json` is an independent conflict even if the binder is
  bypassed.
- Composition binds via 1.2.1, marks, then journals. A refused claim
  does not write bootstrap journal files into an unknown tree.
- Event privacy `restricted`; payload has marker id and fingerprint,
  never the absolute path.

## FIRST-CLAIM POLICY

| Tree | 1.3.1 |
|---|---|
| Directory created during this bind (`created=true`) with only optional `journal/` | claim |
| Empty existing directory | claim |
| Only a Machi journal (`journal/events.jsonl`) | claim |
| Unknown customer-like files | refuse; no marker |
| `.kultrun-owner.json` present | refuse; do not modify |
| Valid `.machi-owner.json` for this fingerprint | re-entry; same identity |
| Marker for another fingerprint | conflict; do not replace |
